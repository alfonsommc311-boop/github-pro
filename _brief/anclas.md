## Área 1 — Fundamentos: qué son Git y GitHub
- **que-son-git-y-github:** Git = control de versiones distribuido (Torvalds, 2005, para el kernel de Linux); GitHub = plataforma que aloja repos Git y añade colaboración (PR, issues, Actions, Pages, seguridad), nacida en 2008, de Microsoft desde 2018. Tabla Git vs GitHub (herramienta local vs servicio; sin internet vs con; gratis y abierto vs planes). Alternativas por nombre (GitLab, Bitbucket) sin comparar cifras. Ejemplo: la app metrados-pro vive en la laptop (Git) y en github.com (GitHub); qué pasa si se pierde la laptop. Vocabulario mínimo: repositorio, commit, rama, remoto, clone, push, pull. Error: creer que "subir a GitHub" es lo mismo que "hacer commit".
- **como-piensa-git:** cada commit es una instantánea completa del proyecto (no un diff), identificada por un hash SHA (40 caracteres; se cita por sus primeros 7); objetos blob, tree, commit; el commit apunta a su padre: la historia es una cadena; cambiar cualquier cosa cambia el hash (por eso reescribir historia "cambia" los commits); casi nada se borra: reflog y objetos huérfanos. Tabla objeto → qué guarda. Ejemplo: mismo archivo en dos commits pesa una vez (deduplicación). Error: pensar que un commit guarda "solo los cambios".
- **las-tres-zonas-de-git:** árbol de trabajo (working tree), área de preparación (staging/index) y repositorio (.git); un cuarto lugar: el remoto. Comandos que mueven entre zonas: add, commit, restore, restore --staged, push/pull. Tabla zona → qué contiene → comando de entrada y salida. Por qué existe el stage (elegir qué entra en cada commit; `git add -p` por trozos). Ejemplo: en word-mcp se cambian tres archivos pero solo dos van en el commit. Error: hacer `git add .` sin mirar `git status`.
- **instalar-y-configurar-git:** instalar en Windows (git-scm.com o `winget install Git.Git`), macOS (brew) y Linux (apt/dnf), por nombre, sin versiones; `git --version`; `git config --global user.name`, `user.email` (debe coincidir con un correo verificado en GitHub para que los commits se atribuyan), `init.defaultBranch main`, `core.editor`, `core.autocrlf` en Windows (concepto: finales de línea), alias útiles (`git config --global alias.st status`, `alias.lg "log --oneline --graph --all"`); `git config --list --show-origin`. Tabla de configuraciones. Error: correo distinto al de GitHub → commits sin avatar ni atribución.
- **tu-cuenta-y-perfil-de-github:** elegir nombre de usuario (aparece en todas las URL; cambiarlo rompe enlaces), verificar correo, activar verificación en dos pasos (Settings → Password and authentication), claves SSH en Settings → SSH and GPG keys, README de perfil (repo con el mismo nombre del usuario, archivo README.md), pines de repos, planes por nombre (Free, Pro, Team, Enterprise) sin precios, organizaciones. Tabla de ajustes recomendados. Ejemplo: perfil de un ingeniero que construye MCP y apps formativas.

## Área 3 — Ramas y fusiones
- **que-es-una-rama:** rama = puntero móvil a un commit (archivo de 41 bytes en .git/refs/heads); HEAD = dónde estás (apunta a una rama o, en detached HEAD, a un commit); crear ramas es instantáneo; main es una rama más; por qué una rama por tarea. Tabla de términos (rama, HEAD, main, upstream, detached). Ejemplo: `git log --oneline --graph --all` con dos ramas dibujadas en texto. Error: trabajar todo en main.
- **crear-cambiar-y-borrar-ramas:** `git branch`, `git branch <n>`, `git switch <n>`, `git switch -c <n>`, `git checkout -b` (clásico), `git branch -d` (fusionada) vs `-D` (forzado), `git branch -m` (renombrar), `git branch -a` y `-vv` (con upstream); convenciones de nombres (feature/, fix/, hotfix/, release/, y las ramas claude/ que crea el asistente); ramas remotas `origin/x`. Tabla comando clásico vs moderno. Ejemplo: rama `feature/lecciones-area-4` en metrados-pro. Error: cambiar de rama con cambios sin commit (Git bloquea o arrastra).
- **merge-fast-forward-y-de-tres-vias:** qué hace `git merge <rama>` desde la rama destino; fast-forward (solo mueve el puntero) cuando no hay divergencia; merge de tres vías (base común + dos puntas → commit de merge con dos padres); `--no-ff` para conservar la forma; `--squash` concepto; `git merge --abort`; ver el resultado con `log --graph`. Tabla ff vs 3-way. Ejemplo numérico de commits A-B-C con dibujo en texto. Error: fusionar desde la rama equivocada (estar en feature y hacer merge main "al revés").
- **resolver-conflictos:** cuándo ocurre (mismas líneas cambiadas en ambas ramas; archivo borrado y modificado); marcadores `<<<<<<< HEAD`, `=======`, `>>>>>>> rama`; leerlos: arriba lo tuyo, abajo lo que llega; resolver en editor o VS Code (Accept current/incoming/both), `git add` y `git commit` (o `git merge --continue`); `git merge --abort`; `git diff` durante el conflicto; conflictos en rebase (`--continue`, `--abort`); herramientas `git mergetool` mención. Tabla de tipos de conflicto y remedio. Ejemplo: dos lecciones editan catalog.js. Error: borrar los marcadores sin decidir y subir un archivo roto.
- **rebase-y-cuando-no-usarlo:** `git rebase main` desde la rama: reaplica tus commits encima (hashes nuevos, historia lineal); merge conserva la historia real; regla de oro: nunca rebase de commits compartidos; `git pull --rebase` para integrar sin commits de merge; `--force-with-lease` para subir una rama propia rebasada (nunca `--force` a secas); tabla merge vs rebase (historia, hashes, seguridad, cuándo). Ejemplo: rama personal atrasada respecto de main. Error: rebasear main y hacer push forzado.

## Área 4 — Trabajar con GitHub: remotos
- **crear-un-repo-y-primer-push:** dos caminos: (A) repo nuevo en GitHub (New repository: nombre, visibilidad, sin README si ya hay proyecto) + `git remote add origin <url>` + `git branch -M main` + `git push -u origin main`; (B) `git clone` y empezar dentro; `-u`/`--set-upstream` guarda el upstream; `git remote -v`; HTTPS vs SSH en la URL; qué aparece en la web tras el push. Tabla de pasos. Ejemplo: publicar cotizador-web por primera vez. Error: crear el repo con README y luego push desde un proyecto con historia distinta (rechazo por historias no relacionadas; remedio: pull con `--allow-unrelated-histories` o empezar sin README).
- **clone-fetch-pull-y-push:** `git clone <url> [carpeta]` (copia toda la historia; `--depth 1` para clon superficial); `git fetch` (descarga referencias, no toca tu trabajo) vs `git pull` (fetch + merge; `--rebase`; `--ff-only`); `git push`, `git push origin <rama>`, `git push -u`, `--force-with-lease`; rechazo non-fast-forward: alguien subió antes → pull, resolver, push; `git remote show origin`; ramas de seguimiento `origin/main` y `git branch -vv`. Tabla comando → qué mueve entre local y remoto. Ejemplo: Alfonso en la laptop y Claude Code en la nube empujando a la misma rama. Error: `git push --force` sobre main.
- **autenticacion-token-ssh-y-gh:** GitHub no acepta la contraseña por HTTPS: Personal Access Token (Settings → Developer settings → Personal access tokens; fine-grained vs classic, permisos mínimos, caducidad) guardado con Git Credential Manager (viene con Git para Windows); SSH: `ssh-keygen -t ed25519 -C "correo"`, clave pública en Settings → SSH and GPG keys, `ssh -T git@github.com`, URL `git@github.com:usuario/repo.git`; GitHub CLI `gh auth login`; cambiar URL con `git remote set-url`. Tabla HTTPS+token vs SSH vs gh. Nunca pegar un token en un archivo del repo. Error: token caducado y "Authentication failed".
- **fork-y-upstream:** fork = copia del repo en TU cuenta; clone del fork; `git remote add upstream <url original>`; rama de trabajo; push a origin (tu fork); PR desde el fork hacia el original ("Compare & pull request"); mantener el fork al día: `git fetch upstream`, `git switch main`, `git merge upstream/main`, push; botón Sync fork en la web; leer CONTRIBUTING.md y CODE_OF_CONDUCT.md; buscar "good first issue". Tabla origin vs upstream. Ejemplo: aportar una corrección a un servidor MCP de terceros. Error: hacer commits en la rama main del fork.
- **readme-licencia-y-archivos-de-comunidad:** README.md (qué es, capturas, cómo instalar, cómo usar, cómo contribuir, badges), LICENSE (sin licencia = todos los derechos reservados; MIT, Apache-2.0, GPL-3.0 por nombre y su idea; elegir al crear el repo), CONTRIBUTING.md, CODE_OF_CONDUCT.md, SECURITY.md, CHANGELOG.md, carpeta .github (plantillas de issue y PR, CODEOWNERS, workflows), .editorconfig mención; About del repo (descripción, topics, web). Tabla archivo → para qué. Ejemplo: README de metrados-pro con sección "Cómo se construye el APK". Error: repo público sin licencia y sin README.

## Área 9 — Git avanzado: deshacer y arqueología
- **reset-revert-y-reflog:** `git reset --soft HEAD~1` (quita commit, deja stage), `--mixed` (por defecto: deja cambios sin stage), `--hard` (borra cambios: peligro); `git revert <hash>` (commit inverso; seguro en historia compartida; `-m 1` para revertir un merge); `git reflog` (movimientos de HEAD, ~90 días por defecto) y `git reset --hard <hash>` o `git branch rescate <hash>` para recuperar; `git restore --source`. Tabla situación → comando → ¿reescribe historia? Ejemplo: recuperar un commit tras un reset --hard equivocado. Error: reset --hard en main compartida y push forzado.
- **stash-y-cherry-pick:** `git stash` (push, con `-u` para sin seguimiento, `-m` mensaje), `list`, `show -p`, `pop`, `apply`, `drop`, `branch`; cuándo (cambiar de rama con trabajo a medias, pull con cambios locales); `git cherry-pick <hash>` (copia un commit a la rama actual, hash nuevo), rangos, `--no-commit`, conflictos; cuándo NO (mejor merge de la rama entera). Tabla comando → efecto. Ejemplo: hotfix en main copiado a release. Error: olvidar el stash y "perder" el trabajo (stash list lo muestra).
- **rebase-interactivo-y-limpiar-historia:** `git rebase -i HEAD~n` o sobre main: pick, reword, edit, squash, fixup, drop, reorder; `git commit --fixup` y `--autosquash`; limpiar una rama antes del PR; conflictos durante el rebase (`--continue`, `--abort`); regla de oro (solo commits no compartidos) y `--force-with-lease`; alternativa: squash and merge en el PR. Tabla acción → resultado. Ejemplo: 9 commits "wip" en 3 limpios. Error: rebase -i sobre main ya publicada.
- **bisect-blame-y-arqueologia:** `git bisect start`, `bad`, `good <hash>`, iterar, `reset`; `git bisect run <script>` automático; `git blame <archivo>` (`-L`, `-w`, `--ignore-rev`), blame en la web; `git log -S "texto"` (pickaxe) y `-G`, `--follow` para renombrados, `git log -- <ruta>`; `git show <hash>:<ruta>`. Tabla pregunta → comando. Ejemplo: encontrar el commit que rompió el quiz de metrados-pro entre 40 commits en unos 6 pasos. Error: buscar a ojo commit por commit.
- **submodulos-worktrees-y-lfs:** submódulo (`git submodule add <url> ruta`, `update --init --recursive`, clon con `--recurse-submodules`, puntero a un commit fijo; molestias) vs subtree mención; `git worktree add ../carpeta rama` (dos ramas a la vez sin cambiar), `list`, `remove`; Git LFS (`git lfs install`, `track "*.psd"`, .gitattributes; para binarios grandes; cuotas: verificar); cuándo usar cada uno y cuándo no. Tabla herramienta → problema que resuelve. Ejemplo: worktree para revisar un PR mientras sigues en tu rama. Error: subir binarios grandes al repo normal.
